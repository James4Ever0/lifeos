## 3. The Plan — Step by Step

### Phase 0 — Today (60–90 minutes, zero code)

- [ ] Create `LifeOS/` folder. `git init`. First commit: this plan + ai-soul.txt (the founding DNA).
- [ ] Write `README.now.md` — the boot file: who you are (10 lines), current goal, current task board link, hive permission dial setting = `human_veto`.
- [ ] Write `未来日记/001.md`: one scene from the future with **sensory anchors** — a place, an amount of money, a smell, a texture. (Per your doc: future diary = reverse prompt engineering = goal anchor for all agents.)
- [ ] Run the first cabinet review: paste one raw page of your writing to an AI with the cabinet prompt (Hunter/Artist/Skeptic/Auditor voices). Save output to `reviews/001.md`. Commit.
- [ ] Create `TASKS.md`: three columns — `seed | doing | done/branched`. Seeds are cheap; only one item in `doing` at a time.

**Exit criteria:** the loop 行动→记录→记忆→灵感 has run once, end to end, with artifacts in git.

### Phase 1 — Week 1–2: The Daily Contract (读者契约)

Daily, 10–20 minutes, fixed format:

```
## YYYY-MM-DD
- anchor: 1 line from 未来日记 (which future am I diffing against today)
- log: what I did / made / felt, with emotion vector [效价, 唤醒度, 掌控感] 0-10
- fork: any rewrite of a past entry → new file in /branches/ (main never overwritten)
- AI delivery: 3 annotations, 1 contradiction found, 1 next writing prompt, 1 branch suggestion
```

- Weekend: 30-min weekly review — score the week (Section 4), merge or kill branches, prune TASKS.md.
- The 4 minimal "reality sensors" (from your doc): one calendar event, one location tag, one spend number, one photo description per day. These keep the AI's feedback from floating free of reality.

**Exit criteria:** ≥10 daily entries, ≥5 cabinet reviews, ≥1 externalization (a message/post/shared file to any human), friction self-rated ≤15 min/day.
**Tripwire:** 3 consecutive missed days → Plan D (Section 5).

### Phase 2 — Week 3–6: Nerves (semi-automation, one script only)

Pick the single most-hated manual step and automate *only that one*:

- voice → text (Whisper or phone transcription) into `inbox/`, or
- `review.py`: CLI that reads the repo, calls an API with the cabinet prompt, appends to `reviews/`.

Also this phase:
- Start `prompts/` as a DAG: each prompt node records `forks_from` and at least one typed edge — `causes / echoes / contradicts / fulfills_future / cherry_pick_candidate` (start with 3 types: `forks_from`, `echoes`, `fulfills_future`).
- 灵感脉冲, manual edition: once a week, deliberately re-read 3 random old fragments (weak similarity, not greatest hits) and note collisions.

**Exit criteria:** retrieval test passes — ask the system "what was I thinking about X around date Y" and get a correct answer in <2 minutes; daily friction <15 min.

### Phase 3 — Month 2–3: The Face and the First Other Person

- First public artifact: a post/demo/doc built *from* the repo. Ugly is fine. Shipped is the point.
- **The one-co-builder attempt** (this is Plan C's front line, mandatory): send the artifact to one named human with a specific low-cost ask ("看一眼，告诉我哪一段你想往下读"). Record the outcome in `veto-log` + `relationships/`.
- First monthly ForkMind ritual: take the month's real decisions, fork two worldlines, interrogate them briefly, record prediction-error vs 未来日记.

**Exit criteria:** one artifact shipped, one human responded (any response, including silence — silence is data), monthly fork review committed.

### Phase 4 — Month 3+: Product, only if the loop has run 60+ days

Now you may design the Kit/ForkMind-class product — the thinking-topology canvas, the agent git, the hive dial as UI — because now it's a report on a working system, not a blueprint. Not before. This is the rule your Worldline-A self begged for.

## 5. Branches — Plan B / C / D

- **Plan B (friction too high):** automate exactly one step (the most-hated one), never more than one per phase. If capture is the pain → voice pipeline. If review is the pain → `review.py`. The system must keep feeling like it feeds you, not the reverse — your own warning: "我被自己造的系统绊住了脚，还以为它在帮我加速。"
- **Plan C (loneliness / stall):** the two-week rule — if 14 days pass with zero externalization, send one artifact to one named human within 48h, with a low-cost ask. Week 8 fallback: open-source the scaffold (README + protocol, not the private logs). Your simulated self was unambiguous: blueprints carry no invitation; only objects do.
- **Plan D (collapse):** minimum viable loop = 10-minute log + one AI reply, everything else suspended indefinitely. Goal is streak survival, not quality. Restart full protocol when one green week returns. Never zero — zero is the only real failure.
- **Branch Z (the seizure you worried about):** if the system starts making life feel *worse* — monitoring replaces living, maintenance replaces making, "先想好再做" returns — that is a synchronization seizure. Regulation per your own question: laws (this document's tripwires), mirrors (monthly ForkMind review), and humans (the touchpoint quota). Commit a `seizure.md` describing what it felt like; that entry is among the most valuable data the system will ever hold.

## 6. The Partnership Protocol — How We Work, Every Session

1. **Boot:** you hand me the DNA — `README.now.md` + `TASKS.md` + last 7 days + anything relevant (as you did with ai-soul.txt today).
2. **Work:** you command; I execute. New ideas mid-task → they go to `TASKS.md` as seeds linked to the current task (your own rule: 新想法提交到子agent，和原事项关联，评估优先级), not chased immediately.
3. **Close:** before closing the window — your "window minimize" idea — I output the session handoff: what happened, what's next, open leads, updated TASKS.md. You commit it. Any future AI (me or another) boots from it in seconds.
4. **Hive dial** stays at `human_veto` by default; `ai_propose_auto_draft` allowed for reviews/; `ai_autonomy_on_branch_only` only inside `/branches/`. Never auto-write to `main`.
